## What is this project?

**Never Again** is a hackathon project for IBM Bob 2.0 that turns incident postmortems into *proven* regression guards. For each postmortem it produces:

1. **Regression test** — must **FAIL** on the buggy commit (assertion failure, not a crash) and **PASS** on the fix commit.
2. **Variant rule** — a Semgrep (or ESLint) rule generalized from the root cause; scans the repo for every other file that has the same mistake.
3. **Variant fixes** — Bob fixes the variants; the verifier reruns until all are closed.
4. **Action-item audit** — every postmortem action item is classified `guarded / partial / unguarded / process-only` with file evidence.
5. **Verdict** — `GUARDED / PARTIAL / FAILED` per incident, written to JSON and visualized on a 3D dashboard.

**Key design principle:** Bob *generates*; a deterministic verifier *judges*. The AI never grades its own homework.

**Demo app:** `shoplite/` — an Express-based e-commerce service with 3 intentionally-planted real-world-style bugs:
- INC-101: Time-zone bug (midnight orders promised wrong delivery date)
- INC-102: Unbounded retries (retry storm during gateway outage)
- INC-103: Null price propagation (`₹NaN` checkout)

## Git tag conventions

Each incident has two annotated tags on the `shoplite/` history:

| Tag | Meaning |
|-----|---------|
| `inc-101-bug` | Commit where INC-101 bug is present (test must FAIL here) |
| `inc-101-fix` | Commit of minimal fix at the seed location only |
| `inc-102-bug` | … |
| `inc-102-fix` | … |
| `inc-103-bug` | … |
| `inc-103-fix` | … |

Planted variants are committed as regular feature work and **intentionally left unfixed** until the guard engine runs.

## Conventions Bob must follow in this repo

1. **Never edit `shoplite/src/`** while writing a regression test or rule. Read only.
2. **Never claim a guard works** without quoting the real verifier output from `reports/INC-10x.json`.
3. **Bug commits are intentional.** Do not fix planted variants outside of task 07b.
4. **All guard work goes in `guards/INC-10x/`.** Never put test or rule files in `shoplite/`.
5. **Process-only action items** (runbooks, on-call changes) must be classified `process-only`. Do not invent code evidence.
6. **The verifier is the source of truth.** If verifier says `FAILED`, fix the guard — not the app.
7. **Secrets policy:** never commit `.env`, API keys, or tokens. The `.bobignore` enforces this.
8. **ESM everywhere** at the root level. Shoplite has its own `package.json`.
9. **Test determinism:** `vitest.config.js` sets `TZ=UTC`. Pass `now` and clients as arguments — no `new Date()` inside logic under test.
10. **Dashboard reads `public/reports/*.json`** — run `npm run sync-reports` after each verifier run before building the dashboard.

## Verifier algorithm (high-level)

```
for each guard.json:
  1. Anti-cheat the test file
  2. Checkout bugRef worktree → run test → expect FAIL (assertion)
  3. Checkout fixRef worktree → run test → expect PASS
  4. Run rule on bugRef → must match seed (file:line ±2)
  5. Run rule on fixRef → must NOT match seed
  6. Run rule on HEAD shoplite/src → collect variants
  7. Check all evidence paths exist
  8. Verdict: GUARDED | PARTIAL | FAILED
  9. Cleanup worktrees (always)
  10. Write reports/INC-10x.json
```

Exit code 0 only if **all** incidents are `GUARDED`.
